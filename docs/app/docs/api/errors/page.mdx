# Error Bodies

Every error response, from any route or from the server itself, has the same
JSON shape and an `application/json` content type:

```json
{
  "error": "not_found",
  "message": "no asset with id 999"
}
```

| Field | Type | Description |
|-------|------|-------------|
| `error` | string | Stable, machine-readable code. Branch on this. |
| `message` | string | Human-readable explanation. Do not parse it. |

The body contains exactly these two fields. Headers such as `Retry-After` are
preserved on the response.

## Error codes

| HTTP status | `error` | When |
|-------------|---------|------|
| `400` | `bad_request` | Malformed query string or path parameter |
| `401` | `unauthorized` | `/metrics` called without a valid bearer token |
| `404` | `not_found` | Unknown asset, distribution or route |
| `405` | `method_not_allowed` | Any method other than `GET` |
| `408` | `request_timeout` | The request exceeded the server timeout |
| `413` | `payload_too_large` | The request body exceeded the size limit |
| `429` | `too_many_requests` | The per-IP rate limit was exceeded |
| `500` | `internal_server_error` | Unexpected server error |
| `503` | `service_unavailable` | The service cannot answer right now |

`GET /health` is a status report rather than an error: it returns its own JSON
status document, with a `503` status while the snapshot is stale.
